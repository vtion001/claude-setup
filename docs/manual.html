Claude Code Terminal Setup

Operating manual — prompt rewriter, status line, panes & sidebar
Machine: AGS-AIDEV001 · Claude Code 2.1.220 · Windows 11 + Windows Terminal
Nothing to set up per session. Everything lives in ~/.claude/, which is user-level — it loads in every session and every project automatically. This manual is about using it.

1 · The prompt rewriter — ctrl+g

Type a rough prompt, press ctrl+g, and it is replaced in place with a sharper version. Takes about 5–6 seconds. A spinner shows elapsed time.

make the login faster
      ↓  ctrl+g
Profile the login flow and identify what is making it slow — server response
time, database queries, and frontend asset loading. Fix the biggest bottleneck
you find and measure the before and after.

It reads the recent conversation, so references resolve:

push it   →   Sync and push the prompt-rewriter bundle to the private repo
              at github.com/vtion001/claude-setup

What it will and will not touch

You typedWhat happens
normal textrewritten, sharper
+textrewritten, also loading the project's own CLAUDE.md
/skills · any /cmdleft alone — a reworded command stops resolving
[Image #1] · [Pasted text #2]left alone — rewording detaches the file
#noteleft alone — memory write
"do it", "the second one"resolved from the conversation; left alone if genuinely unresolvable
emptynothing happens
It never opens an editor. $VISUAL is the rewriter, so ctrl+g and ctrl+x ctrl+e both run it. There is no external-editor path from inside Claude Code any more — use the IDE extension if you need one.

Recovery

  • Your text before the last rewrite: ~/.claude/prompt-boost.last.txt
  • One line per keypress, with the reason: ~/.claude/prompt-boost.log

Topuser@host, model, effort level, FAST/agent/remote badges, clock

3 · Keyboard reference

Inside Claude Code — ctrl+k then a letter

These drive Claude Code's own diff panel and session tabs, which ship unbound.

KeysAction
ctrl+grewrite the prompt you are typing
ctrl+k dtoggle the diff panel
ctrl+k fshow / hide tests in the diff
ctrl+k bcycle the diff base
ctrl+k sshow / hide pre-session changes
ctrl+k tnew session tab
ctrl+k n / pnext / previous tab
ctrl+k 1–3jump to tab
The diff panel needs a git repo and a wide terminal. It declines silently otherwise — that is not a fault.

Panes — alt+shift + key

Windows Terminal, not Claude Code. The alt+shift prefix is deliberate: Claude Code itself owns plain alt+p/o/t/w/v/j and alt+↑/alt+↓.

KeysAction
alt+shift+sopen the sidebar pane (right, 32%)
alt+shift+e / osplit right / split down
alt+shift+←↑↓→move focus between panes
alt+shift+, / .resize the pane
alt+shift+zzoom the focused pane full screen
alt+shift+wclose the pane
alt+shift+dduplicate pane

4 · The sidebar

Claude Code has no file explorer and no way to view an arbitrary file — its only panel is hardcoded to git diffs. The sidebar fills both gaps from a pane beside it. Open it with alt+shift+s.

ModeShows
no targetfile tree of the current repo, via git ls-files — so .gitignore is respected and node_modules never appears
a targetthat file with line numbers, re-rendering when it changes

Point it at a file:

echo C:/path/to/file.php > ~/.claude/sidebar.target   # show a file
: > ~/.claude/sidebar.target                          # back to the tree

Or simply ask Claude — "show config/qarubric.php in the sidebar" — and it writes that file for you.

The root follows whichever project your newest live Claude Code session is in, so it tracks you across projects automatically. Override with -Root.

Still no in-app editor. Claude Code's binary has no text-editor component and one cannot be added. To edit, focus the sidebar pane and run vim or nano there.

5 · Troubleshooting

SymptomCause and fix
Rewrite takes >10s MAX_THINKING_TOKENS=0 should be set on the subprocess in prompt-boost.ps1. Without it the model burns ~1,500 thinking tokens and takes 13–26s instead of ~5s.
Rewriter asked a question
instead of rewriting		 It could not resolve a reference. The script discards that output and keeps your original — look for REJECTED in prompt-boost.log.
Status line blank It exits silently on a JSON parse error. Test by hand (§6). A byte-order mark in the payload will break it.
Background missing Must be in profiles.defaults, not one profile. Check useAcrylic:false and opacity:100. Windows Terminal reverts to built-in defaults on any JSON error.
Boxes instead of glyphs Set $NERD = $false near the top of statusline.ps1.
Diff panel will not open Not a git repo, or the window is too narrow. Both are silent.
Pane keys do nothing You are not in Windows Terminal — the VS Code integrated terminal and mintty do not have these.

6 · Verifying it works

powershell -NoProfile -File ~/.claude/statusline.ps1 < ~/.claude/statusline.last.json
powershell -NoProfile -File ~/.claude/prompt-boost.ps1 -Probe    # session + context
tail -5 ~/.claude/prompt-boost.log

To capture a fresh status-line payload: touch ~/.claude/statusline.debug, restart, inspect statusline.last.json, then delete the flag file.

7 · Rebuilding on a new machine

git clone https://github.com/vtion001/claude-setup
cd claude-setup
powershell -ExecutionPolicy Bypass -File .\install.ps1 -DryRun   # preview
powershell -ExecutionPolicy Bypass -File .\install.ps1           # apply

The installer restores ~/.claude/, merges the Windows Terminal background and all pane bindings, rewrites this machine's hardcoded paths, and backs up anything it replaces. Then: run claude, /login, and restart Windows Terminal.

The export goes stale the moment anything changes here. Re-sync and push after touching prompt-boost, sidebar, statusline or the keybindings — otherwise a rebuild silently installs the old behaviour.
