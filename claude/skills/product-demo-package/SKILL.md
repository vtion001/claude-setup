# Product Demo Package

## Overview
Turn a running web app into a stakeholder-ready package: a **hybrid demo video** (real Playwright screen-capture composited in Remotion — a cold-open hook, branded intro, timed captions, a cursor anchored to real DOM elements, a proof/payoff beat, a CTA outro) plus **brand-styled PDFs** generated by parallel agents from the codebase, then delivered. All heavy tooling runs inside the Playwright Docker image; the only host install is the Remotion CLI/MCP.

**This is the primary template — not a worked example among options.** Every prior
iteration (single-clip capture, hand-typed cursor coordinates, hardcoded look, no
narrative layer) is superseded, not preserved as an alternative. A new invocation of
this skill should always produce output in this shape: DOM-anchored per-scene capture,
calibrated cursor, config-driven look, and the hook→brand→scenes→proof→CTA narrative
arc — never fall back to an earlier, simpler pipeline because it's less work.

**The look is data, not code.** `demo.config.js` (preset + brand tokens + motion +
narrative + scenes + targets) is the single artefact the whole pipeline reads. Never
edit the aesthetic, the cursor path, or the narrative copy inside the Remotion
component — all three are config, not implementation.

## When to use
- "Make a demo video / product walkthrough / record the app."
- "Write system documentation / a migration plan / a meeting brief" as a polished PDF.
- "Package deliverables for [stakeholder]" and send them somewhere.
- NOT for: a quick screenshot (just use Playwright), or docs that don't need brand-quality PDF output.

## MANDATORY intake — ask before capturing

Do not start capture until these five groups are answered. **Never assume the look,
and never assume the story.** Across three builds the look was assumed each time —
light, then dark, then cinematic — and was wrong twice. Everything after this section
exists to make the answers actionable.

1. **Look & stage** — which preset (`clean-light`, `cinematic-dark`, `brand-derived`), then accent colour. Offer to sample the accent from the running app.
2. **Audience & genre** — `explainer`, `sizzle`, or `both`; rough target length.
3. **Motion intensity** — `subtle` / `standard` / `cinematic`. Independent of preset: a light stage can carry cinematic motion.
4. **Per-screen action** — for each route, which element matters and whether it is safe to click.
5. **Hook, proof & CTA** — see "Narrative & engagement" below. Ask for the pain point, the ONE number that proves it's solved, and the next step — do not write these yourself.

**Question 4 is only answerable if you do the work first.** Run
`scripts/discover-targets.mjs` against the app; it enumerates visible, labelled,
interactive elements per route with a stable selector and real bounding box, then
present *those* as the options. The user cannot be asked to hand-write CSS selectors,
and offering invented ones is how the cursor ended up pointing at nothing.

**Question 5 carries the same rule, applied to copy instead of pixels.** A hook,
proof stat, or CTA invented for effect is the exact defect the DOM-anchored cursor
work exists to prevent, just moved from coordinates to prose. If the user has no
number ready, use `docs-only`/no-narrative mode (below) rather than write one.

If `demo.config.js` already exists, show the current answers and offer
*reuse / change look / change targets / change narrative* instead of re-asking everything.

### Presets

| Preset | Surface | Panel | Accent | Motion |
|---|---|---|---|---|
| `clean-light` | `#FFFFFF` | `#1C1C1C` bezel, radius 20 | project brand | standard |
| `cinematic-dark` | `#06060B` → `#150F26` | `#141419`, rim light | `#A78BFA` | cinematic |
| `brand-derived` | sampled from the running app via `getComputedStyle` | derived | sampled | standard |

A light surface **requires** the dark bezel — a light app UI on a white canvas has no
separation other than corner radius, and the footage stops reading as an object. That
is a constraint of the preset, not a preference.

### Pacing

`motion.rhythm` alternates stage brightness scene-to-scene; `brand.hueDrift` rotates the
key light a few degrees per scene. Both default **on** for `cinematic`, **off** for
`subtle`. Reference product films swing frame luminance by ~40x and shift cool→warm
between sections; builds that hold one stage, one accent and one brightness for their
whole runtime read as handsome but monotonous. This is the fix for "it's nice but boring".

## Narrative & engagement

Everything above this line makes the video look like professional footage. None of it
makes anyone *care*. A cinematic recording of a feature nobody was worried about is
still skippable. This section is the difference between an editor and something that
hooks a viewer — grounded in tested video-marketing research, not house style.

**The one rule that governs all of it: a hook, proof number, or CTA is a claim, and
claims get sourced or asked for — never invented.** This is the same discipline
`targets[]` applies to cursor coordinates, moved from pixels to prose. A stakeholder
video with a fabricated statistic is worse than one with no narrative layer at all.

### The structure: Hook → Brand → Scenes → Proof → CTA

Composited by `Demo.jsx` from `config.narrative`, all four fields optional — omit
`narrative` entirely and the video renders exactly as the pre-narrative pipeline did.

```js
narrative: {
  hook:  '{{4,984 conversations.}} Every one had to be traced back by hand.',
  proof: '{{4,975}} were recovered automatically.',
  cta:   { line1: 'Ask for a walkthrough on your own data.', line2: 'Tenant-isolated by design.' },
},
```

`{{...}}` marks the fragment rendered in the accent colour, full weight — the
isolation styling described below. Everything else renders in the normal text colour.

- **Hook (cold open, no branding).** Leading with a logo before the viewer has a
  reason to care is a documented retention anti-pattern — brand recognition is not
  relevance. The hook plays first, sober, no sparkles: it names the problem
  (StoryBrand's "agitate" beat), it does not yet introduce the product.
- **Brand reveal**, immediately after, short.
- **Scenes**, unchanged — this is where the DOM-anchored cursor work does its job.
- **Proof**, right before the outro. Same isolation styling and screen position as
  the Hook, on purpose — see "Open loops" below.
- **CTA**, folded into the outro title: one concrete next step, not a slogan.

### Four hook archetypes (pick one in question 5)

| Archetype | Pattern | Use when |
|---|---|---|
| Pain-point | "Still `{{doing X the slow way}}`?" | The audience already recognizes the friction |
| Bold claim | A specific, falsifiable statement + the footage that proves it | You have a number strong enough to state flatly |
| Curiosity gap | An incomplete frame that demands the next beat resolve it | The payoff is worth the wait and WILL land — see the warning below |
| Stat-led | Open cold on the number itself | The number is the whole argument |

Score a candidate hook against **NERV** — Novelty (does it look different from what
usually plays here), Emotion (immediate reaction), Relevance (self-identifies as "for
me"), Void (creates a question the next beat must answer). A hook that's true but
inert on all four axes isn't wrong, just not doing its job.

**Warning on curiosity gaps: the payoff must actually deliver.** An unresolved gap
doesn't create engagement, it creates distrust the second time.

### Open loops (Zeigarnik effect)

The brain holds an incomplete task in a way it does not hold a completed one — the
classic finding is waiters recalling unpaid orders and forgetting them the instant
payment lands. Applied here: **the Hook and Proof beats bookend the same real number**,
so the Proof beat reads as closing something the viewer noticed a few seconds earlier,
not as a new, disconnected statistic. This only works with ONE number carried through —
bookending a different metric in Hook and Proof breaks the loop instead of closing it.

### Isolation styling (Von Restorff effect)

A 500-person replication found a single number in a different colour was recalled
**30× more often** than its plain neighbors in the same list. Isolated items in the
original research were recalled at roughly double the rate of non-isolated ones. The
mechanism in this skill is literal: `{{fragment}}` renders in the accent colour and
full weight, the rest of the sentence does not. Use it on exactly the load-bearing
number or phrase — isolating everything isolates nothing.

### Pacing: pattern interrupts

Research on retention editing gives a concrete check, not a vibe: **scan the timeline
for any 5-second span with no cut, zoom, text change, or sound change, and put
something there.** Cadence depends on audience — B2B/considered-purchase content holds
8–10s between interrupts; fast-scroll/attention-scarce content wants 3–5s. This
pipeline already satisfies the check by construction: the DOM-anchored cursor is always
moving to the next target, `rhythm`/`hueDrift` change the stage between scenes, and the
sizzle cut (`Sizzle.jsx`) is built on ~2.3s hard beats already. Nothing to add — this is
a check to run before treating a build as done, not a new component.

### CTA — one concrete next step

The 5-part SaaS-explainer arc (Hook → Problem → Solution → Proof → CTA) ends on a
single, low-friction, specific action — not a tagline. "Built to be seen" is a slogan;
"Ask for a walkthrough on your own data" is a CTA. For an internal/stakeholder demo
(this skill's usual context, not a cold-traffic ad) the CTA is the realistic next
step for THAT audience — a rollout conversation, a request for access, a follow-up
meeting — never invented urgency or a discount that doesn't exist. Cialdini's
persuasion principles are worth knowing (reciprocity, commitment, social proof,
authority, liking, scarcity, unity) but the only two that translate honestly to an
internal product demo are **social proof** (a real usage number) and **authority**
(a real capability, shown working) — manufacturing scarcity or urgency in a stakeholder
deck reads as exactly what it is.

### No-narrative mode

If question 5 comes back with no usable number or CTA, leave `narrative` out of
`demo.config.js` entirely. The Hook and Proof beats collapse to zero duration and the
video renders identically to the pre-narrative pipeline — a video with a real,
DOM-anchored cursor and no story layer is a complete, honest deliverable. A video with
an invented story layer is not.

## Workflow
Full step-by-step with exact commands: **`references/runbook.md`**. Summary:

1. **Intake** (above) → write `demo.config.js`.
2. **Docs — parallel agents.** One general-purpose agent per document; each writes ONE Markdown file and verifies every claim against the code. Templates + anti-hallucination guardrails: `references/doc-agent-prompts.md`.
3. **Docs → PDF.** `scripts/make-pdfs.mjs` renders each Markdown to a brand-styled A4 PDF, importing the SAME tokens as the video.
4. **Seed a call-free demo state.** `scripts/demo_seed.php` populates the demo record with real data and pre-warms any external-API cache, so the walkthrough fires no live third-party calls.
5. **Capture.** `scripts/demo-capture.spec.js` records **one clip per scene**, drives the **real mouse** to each configured target, and logs the movement as `<id>.cursor.json`.
6. **Build.** `scripts/build-scenes.mjs` measures each trimmed clip and merges its cursor timeline into `scenes.json`.
7. **Render.** `npx remotion render src/index.jsx Demo out.mp4 --gl=swangle` (plus `Sizzle` when the genre includes it).
8. **Deliver.** PDFs + MP4 + README in one folder; `scripts/send-telegram.sh` uploads them.

## The cursor must be anchored to real elements

The single most important rule in this skill.

Do **not** hand-write cursor coordinates. Percentages typed into the component point at
whatever happens to occupy that fraction of the frame, and because the footage was
recorded before the coordinates existed, nothing hovers, focuses or reacts underneath
them. It reads as a sticker on a video.

Instead, declare targets in `demo.config.js`:

```js
targets: [
  { sel: '#status', dwell: 700, label: 'Status filter' },
  { sel: 'button.filters', dwell: 900, click: true, label: 'More filters' },
]
```

Capture resolves each with `locator(sel).boundingBox()`, moves the real mouse there in
eased steps, dwells so hover/focus states are visible, and logs `{t,x,y}` plus the
element's real `w`/`h`. The render replays those samples: the focus ring is sized from
the recorded box, and motion blur comes from measured velocity between consecutive real
samples. The drawn cursor and the UI's own reaction cannot drift apart, because both
derive from the same movement.

**Hover-only by default.** `click: true` is opt-in per target — a click in a demo run
can fire a sync, a batch job, or something destructive. A good click target produces a
visible reaction and mutates nothing (a tab switch, a filter panel).

**The inner surface must match the capture aspect ratio exactly.** If `objectFit` crops
or letterboxes the footage, every coordinate lands slightly wrong and the bug is back.

## Calibration — measure the offset, then cut the marker

`recordVideo` gives no frame-accurate mapping from wall-clock to video frames. Unmeasured,
a 200ms error puts the cursor behind the highlight it is supposed to be causing.

1. Once the page has **painted** (not at page creation — see gotchas), flash a
   full-viewport magenta `#FF00FF` field for ~160ms. `t0` is that instant.
2. Find it by decoding the clip at 8×8 with `showinfo` and testing for a magenta
   histogram; `pts_time` gives the real timestamp with no fps assumption.
3. **Not found → throw.** A silently unaligned cursor is worse than a failed build.
4. Trim the clip just past the marker, rebase the timeline by the same amount, and set
   `offsetMs` to 0 — so the render performs no offset arithmetic at all.

## Adapt for your app

| File | Change |
|------|--------|
| `demo.config.js` | **Everything app-specific lives here**: preset, brand tokens, motion, output genre, watermark, `narrative` (hook/proof/CTA — optional), and per-scene `url` / `settle` / `caption` / `targets`. Generated by the intake. |
| `demo_seed.php` | The **concept**, not a universal script — rewrite its body for YOUR data model. Its job: real-looking data AND a warmed external-API cache so the walkthrough makes no live third-party calls. |
| `make-pdfs.mjs` | `DIR`, `DOCS[]` (md→pdf), cover kicker + author. Brand tokens are imported, not redefined. |
| doc-agent prompts | App name, the file list to verify against, guardrail facts, section structure, screenshot paths. Screenshots are optional — the prompt `ls`-verifies before embedding. |
| `discover-targets.mjs` / `demo-capture.spec.js` login step | Login path and field selectors are copied from the last app adapted — check them against the new app's actual login markup. |
| `remotion/package.json`'s `render` script | Composition id must match what `Root.jsx` registers — a leftover id from a prior app's template renders nothing. |

Nothing in `Root.jsx` or `Demo.jsx` should need editing for a new app. If you find
yourself editing them, the thing you are changing probably belongs in the config.

## Non-obvious gotchas (each one cost a real debugging cycle)
- **The scene ENTRY animation must finish before the first target.** Capture starts moving the mouse ~0.5s into the clip; a 1s entry meant the most important moment — the first hover — played under heavy motion blur at a 26° tilt. Keep the entry ≤16 frames, or add a lead-in hold before the first move. Only a frame montage reveals this; it looks fine while scrubbing.
- **Flash the calibration marker AFTER the page paints, not at `newPage()`.** On `about:blank` it races the encoder's first frame — it was missed entirely on one scene in three. Flashing it post-settle also means the trim discards the page LOAD, so every scene opens on a settled page.
- **Pin `playwright` in `package.json` to the EXACT Docker image tag.** A `^1.59.1` range resolved to 1.62.1 against the `v1.59.1` image and the browsers were missing.
- **`npm i --no-save <pkg>` in a directory with no `package.json` PRUNES existing extraneous packages.** It silently removed playwright mid-build. Keep a real manifest in `/work`.
- **Pages holding an SSE/EventSource stream never reach `networkidle`.** `waitUntil:'networkidle'` hangs to timeout and records one motionless screen (a 40s clip, once). Use `settle: 'domcontentloaded'` for them.
- **A `Secure` session cookie is dropped over `host.docker.internal`** (localhost gets a trustworthy-origin pass; that hostname over plain HTTP does not), so every POST 419s. Serve with `SESSION_SECURE_COOKIE=false` for the capture, and **throw** if the post-login URL is still `/login` — swallowing it produced a "successful" render in which every scene was the login screen under a caption describing a feature.
- **Set `users.onboarded_at` (or the app's equivalent) before capturing** — a first-login product tour will hijack every scene.
- **One clip per scene removes the timing gotcha entirely.** Caption windows bind to a scene, not to a wall-clock offset that shifts with page-load speed. Durations are still MEASURED with ffprobe, never typed.
- **Run all Node/Chromium/ffmpeg via `mcr.microsoft.com/playwright:v1.59.1-noble`** (`docker run --rm -v "$PWD":/work -w /work …`) **on Windows/WSL** — host npm on `/mnt/c` throws `EACCES` (drvfs); in Git Bash, prefix with `MSYS_NO_PATHCONV=1` or `/work` gets rewritten to a Windows path. **On native macOS this constraint doesn't apply** — `npm install playwright @ffmpeg-installer/ffmpeg @ffprobe-installer/ffprobe` + a global Remotion CLI run entirely natively with no Docker at all (verified end-to-end 14 Aug 2026); use relative paths (`./footage`) instead of `/work/footage` throughout the capture/build scripts when running this way.
- **ffmpeg is NOT on the image's PATH**, and Playwright's bundled build is VP8-only. Use `@ffmpeg-installer/ffmpeg` / `@ffprobe-installer/ffprobe` and call their `.path`.
- **Use `spawnSync`, not `execFileSync`, when you need stdout AND stderr from one ffmpeg decode** — pixels on stdout, `showinfo` timestamps on stderr, guaranteed to describe the same frames.
- **Transcode scene clips to H.264** on trim (`-ss` AFTER `-i` for frame-exact output seeking). It decodes far faster in Remotion than VP8 and the clips are short enough that the re-encode is free.
- **Playwright's Chromium has no PDF viewer** — an iframe pointing at a PDF captures blank. Composite the page as a rasterized-image overlay (`pdftoppm`) instead.
- **Remotion render needs `--gl=swangle`** on headless Linux.
- **ESM helper scripts** need their imports in the **project** `node_modules`; `NODE_PATH`/global installs won't resolve.
- **Telegram creds live in the workspace `CLAUDE.md`** — never hardcode; verify `"ok":true` on every send.
- **Remotion's `staticFile()` only resolves inside the Remotion project's own `public/` dir** — if capture writes clips to a sibling `footage/` directory (the natural layout when the Remotion project lives in a subfolder), the render 404s on every clip. Symlink it in: `ln -sf "$(cd .. && pwd)/footage" public/footage`.
- **`brand-derived`'s preset tokens (`surface`/`text`/`muted`/`accent`/`font`) are `null` by design** until resolved to literal values (see `presets.mjs`'s own doc comment) — declaring `preset: 'brand-derived'` with only an `accent` override and no other literal values crashes `Demo.jsx`'s `hexToRgb` on `null.replace`. Fill all of them with real values (sampled or from the app's own documented brand tokens) in `demo.config.js` before rendering.
- **`discover-targets.mjs`/`demo-capture.spec.js`'s login step and `remotion/package.json`'s render script id are copied from whichever app they were last adapted for** — not generic. Check both against the new app: login path/field selectors (`input[name=...]` won't match a Vue SPA with no `name` attrs — use `input[type="email"]` etc.), and the render script's composition id must match what `Root.jsx` actually registers (`Demo`, not a leftover app-specific id). **Check the target app's own e2e test suite first** (a `global-setup.ts` or similar) — many apps already have a working direct-API-POST-login-plus-cookie pattern for automated auth; reusing it is faster and avoids rate-limiting the real login route (confirmed 14 Aug 2026, adapted from an existing Playwright e2e setup rather than reimplementing UI login).
- **Client-state tab-switching apps have no per-tab URL** — some admin/dashboard UIs are a single route where a sidebar click flips React state (`activeTab`/`setActiveTab`) instead of navigating. `discover-targets.mjs`/`demo-capture.spec.js`'s URL-per-scene assumption doesn't apply: click the real nav element, wait for the new panel to settle (retry-until-`aria-current` to defeat a hydration race where a pre-hydration click is a silent no-op), THEN discover/target the now-visible DOM — confirmed 14 Aug 2026 on an 18-tab single-route admin dashboard.
- **When the app's content lives inside a centered max-width container, capture at the container's natural size, not the output canvas size.** Capturing at the full 1920-wide canvas framed the content with ~640px of empty margin either side; capturing at 1440×900 (matching the `max-w-7xl` container) and letting Remotion stage that footage on the larger canvas kept the content clean with no cursor drift (aspect ratios still matched exactly).
- **Footage containing real customer/user PII is an internal deliverable, not a shareable one by default** — don't attach it to a shared/public location without checking size AND access-control fit first; deliver it directly to the requester when the natural destination can't hold it privately or the file is too large (confirmed 14 Aug 2026: a 29.6MB real-data capture didn't fit a ~2MB internal-tool attachment cap anyway, so direct delivery was correct on both grounds).

## Common mistakes
- **Assuming the look instead of asking.** The most expensive mistake in this skill's history.
- **Hand-writing cursor coordinates.** They point at nothing and the UI never reacts.
- Uniform lighting for the whole runtime → handsome but monotonous. Use `rhythm` + `hueDrift`.
- Clicking without checking what the click does. Hover-only is the default for a reason.
- Watermarking over the footage continuously — no reference-grade product film does this. Cards only.
- Trying to make a PDF pane render inside the capture → wasted effort; overlay it in Remotion.
- Installing tooling on the host → `EACCES`/slow. Use the Docker image.
- Hardcoding secrets into scripts → read them from `CLAUDE.md` at runtime.
